# Signature Web Design

Build a distinctive, polished marketing experience in the user's existing application. The reference library supplies composition and interaction knowledge; the host project supplies architecture and business behavior.

## Inspect and choose

Read the project's local instructions and inspect the target route, its view/component, parent layout, styling pipeline and installed interaction libraries. Trace forms and primary actions before changing markup. If the target is ambiguous, inspect likely entry points and clarify only when choosing would affect unrelated pages.

Read [the catalogue](references/catalogue.md), then the selected reference dossier. Start with a coherent base. Combine individual patterns only when typography, spacing, shapes and motion remain consistent. If no reference fits, derive a new direction from the supplied material and say the catalogue does not yet cover it; do not pretend a reference exists.

For existing applications, read [stack adaptation](references/stack-adaptation.md). For complex movement, read [interaction recipes](references/interactions.md).

## Design and implement

Briefly state the direction and files being targeted, then implement. Do not insert an approval checkpoint unless a consequential missing choice requires it.

Define page-level tokens, headline hierarchy, section rhythm, image treatment and one signature composition. Carry the chosen grammar across the whole page, including navigation and footer. Translate the business content into a deliberate narrative; the reference's section count and order are not mandatory.

Use supplied facts and working destinations. Preserve route helpers, server variables, localization, form actions, validation, CSRF tokens, authentication conditions, analytics hooks and existing interaction bindings. A visual redesign does not authorize replacing working behavior with placeholder links or simulated submissions.

Implement directly in the native files. Reuse the installed styling and animation tools. No separate generator, JSON plan, Node runtime or component registry is required by this skill. Do not scaffold another application or install a framework to apply a reference. Keep page-specific styles scoped when layouts are shared.

Use original copy and visuals supplied by the user or available with appropriate permission. The library contains independently written design recipes, not source assets or template code. Do not transplant source brand names, copy, logos, remote asset URLs or generated class identifiers. Neutral names are used for references and prompts; these names do not grant reuse rights. Record actual provenance separately when adding references.

## Render and refine

Read [visual verification](references/visual-quality.md). Use the project's build and available browser tools. Inspect desktop and narrow-screen renders, exercise actual actions, and refine the most consequential defects, normally within three focused passes. If tools or runtime are unavailable, complete supported checks and identify the unverified behavior honestly.

Deliver the edited files, the visual direction, checks actually performed and remaining limitations. Do not publish as part of applying this skill unless requested.

## Extend the library

When asked to add a visual reference, read [reference intake](references/reference-intake.md). Add a neutral dossier and catalogue entry, distinguishing observed measurements, interpretations and unverified behavior. Never claim visual parity from a text analysis alone.
