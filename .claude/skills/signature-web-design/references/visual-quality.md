# Verify the actual page

Use the host's available checks, then inspect a desktop viewport around 1440px and a narrow one around 390px, plus an intermediate width when composition changes. These are starting points, not a promise of device coverage.

Review the complete page and at least the hero at readable scale. Check heading wraps, whitespace rhythm, contrast, crops, missing images, font loading, overflowing content and the transition between light and dark sections. Test at increased text size where feasible.

Exercise navigation, mobile menu, primary CTA, service tabs, carousel controls and existing forms. Check keyboard focus, reduced motion, console errors and horizontal overflow. Check that the backend action still receives the correct fields when a safe test environment allows it; do not submit real external transactions merely to verify styling.

Compare against the selected composition principles, not a fabricated aesthetic score. Fix the three highest-impact defects first and recheck affected views. If browser inspection is unavailable, state that explicitly; a passing build is not visual verification. Record only screenshots and checks actually produced. No obligatory report files or project configuration changes are needed for a small redesign.
